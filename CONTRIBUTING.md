# Contributing

Thank you for helping improve this project.

This repository is a documentation project for social login setup. Contributions should stay simple, beginner-friendly, and grounded in the latest official provider guidance.

## How to Contribute

You can help by:

- fixing incorrect instructions
- reporting outdated provider UI
- adding a new provider
- improving explanations for non-technical clients
- adding troubleshooting guidance
- fixing broken links
- improving SEO without keyword stuffing

## Adding a New Provider

A new provider should not be added casually. A provider guide should include:

1. Official documentation research
2. A provider-specific guide
3. Clear client/developer responsibility separation
4. Explanation of the required credentials
5. A security section
6. Troubleshooting guidance
7. FAQ
8. Final checklist
9. Official references
10. Manual verification before marking the guide as verified

If a guide is added before the process is manually checked, it should be labeled clearly as not yet verified.

## Accuracy Rule

Never guess provider instructions.

If the current dashboard or provider docs are unclear, do not invent steps. Instead:

- check the official provider documentation
- compare with the live provider dashboard
- note the ambiguity
- ask for clarification or document the issue as pending verification

## Security Rule

Never commit or include any of the following in documentation, examples, screenshots, or pull requests:

- passwords
- client secrets
- private keys
- tokens
- recovery codes
- real customer credentials

If a provider error includes a secret or token, remove it before sharing any example or report.

## Pull Request Expectations

A good pull request should include:

- a clear summary of the change
- the provider or section being updated
- the official source(s) reviewed
- any known limitations or verification status
- links only to relevant documentation
- no fake credentials, screenshots, or secret values

Keep the wording simple, practical, and beginner-friendly.

## Provider Dashboard Changes

Provider dashboards can change at any time. If a contributor notices outdated UI, changed menu names, new permissions, or new approval requirements, they should report it clearly.

A useful report should mention:

- the provider name
- the area of the guide that is outdated
- what changed in the dashboard or workflow
- the official source showing the current process
- whether the issue affects a specific setup step or a wider guide

## Review Standard

Contributors should aim for documentation that is accurate, easy to understand, and clearly labeled when verification is still pending.

If a guide is not yet manually checked against the current provider flow, it should not be presented as fully verified.

## Final Note

This project exists to help non-technical clients understand what they need to provide, what must stay private, and how the developer and client roles fit together.

Please keep the project practical, careful, and honest.
